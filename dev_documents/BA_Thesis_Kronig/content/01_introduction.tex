\section{Motivation}
Mobile applications (apps) can have a variety of vulnerabilities. Modern Android apps have on average a surprisingly large number of vulnerabilities, which greatly impact their security and usage \todo{Add any of the papers read here that say this}. Because of this, it is of great importance to have tools that can detect vulnerabilities, both statically by inspecting the code and dynamically by executing the code and inspecting it at runtime. But how can the effectiveness of these tools be measured and compared to one another? 
To measure the effectiveness of the tool, it is just as important to know how many vulnerabilities a tool was not able to detect, as it is important to find vulnerabilities themselves. Since most real-world mobile apps are closed source \todo{Probably add source for this}, there is no ground truth against which the performance of a vulnerability analysis tool on such apps can be evaluated, making it impossible to use them for measuring the effectiveness of such tools. To measure and compare the effectiveness of existing analysis tools, they have to be evaluated on intentionally vulnerable apps, of which the existing vulnerabilities are known to the person conducting the tests. 

One such dataset of intentionally vulnerable apps is maintained by OWASP MASTG \cite{owasp_reference_app_website}. The issue with many of these apps is either a lack of source code and/or a lack of documentation of the implemented vulnerabilities, making them unfit for benchmarking vulnerability assessment tools. The goal of this BA thesis is to develop our own intentionally vulnerable OWASP MASTG reference apps, which can then be used for evaluating and benchmarking DAST (Dynamic Application Security Testing) and SAST (Static Application Security Testing) tools.

\section{Objectives of the Thesis}
The objectives of this thesis largely concern multiple developing open-source OWASP MASTG reference apps that include both static and dynamic security vulnerabilities. The goal is to cover multiple OWASP MASVS vulnerability categories, focusing on vulnerabilities that have seen little to no coverage in existing OWASP MASTG reference apps. The documentation of the implemented vulnerabilities should be thorough and include: the overall list of implemented vulnerabilities, the mapping to their respective OWASP MASWE counterparts, and a detailed explanation for each vulnerability, documenting where it can be found, how it has been implemented, and how it can be exploited.

The thesis will include an analysis of existing OWASP MASTG reference apps, as to figure out the state-of-the-art in intentionally vulnerable Android app design.
