\chapter{Future Work}
\label{c:future_work}

While the apps we developed significantly helped increase the coverage of different MASWE vulnerability types, there are still many such vulnerability types that lack a reference implementation. There are still 57 vulnerabilities that do not have any representation in the MASTG reference apps, including our own. This means that only 51.3\% of all vulnerability types are included in the apps catalog. Our work can be expanded upon by moving on to new MASVS categories, designing and implementing vulnerabilities in a way similar to our methodology. The categories MASVS-AUTH and MASVS-PRIVACY are of special interest, since they have the lowest remaining ratio of described-to-implemented vulnerabilities, with only 2 out of 20 and zero out of nine vulnerability types, respectively, seeing any implementation and coverage in the reference apps.

Our work is not only motivated by improving the educational value of the OWASP MASTG reference apps, but also its ability to be used for benchmarking SAST and DAST tools. We have tested different static security testing tools, such as MobSF, on our apps, but benchmarking and properly evaluating and comparing the different tools making up the modern mobile testing tools landscape lies outside the boundaries and resources of our work. A natural next step would be to carry out a scientific evaluation and benchmarking process of relevant and modern mobile app testing tools of both static and dynamic nature. Furthermore, their performance on our apps can be compared to their performance on other MASTG reference apps, as well as other existing mobile security tool testing benchmarks. This way, value our developed apps hold in terms of testing such tools can be measured.

Since the Android application landscape and its vulnerabilities are constantly evolving, and the OWASP MASTG alongside it, it is an important next step to uphold maintenance of our developed apps. MASWE vulnerabilities and tests are constantly being deprecated and replaced with new ones. Even the MASVS categories themselves can change, with the most recent addition being MASVS-PRIVACY. Because the MASTG reference apps can only hold their value both as a learning resource and a security tool benchmarking dataset if they keep up with the changing Android vulnerability landscape as described by the OWASP MAS project, our apps need to receive constant updates.

The OWASP MAS project does not concern itself exclusively with Android security vulnerabilities, but has a similar if somewhat smaller segment dedicated to the mobile security of iOS applications as well. It is common belief that iOS apps have better security standards due to the more regulated nature of the app platforms from which apps are distributed. There are however many security flaws and vulnerabilities iOS apps can include, as described by the related OWASP MAS fields. Steinböck et al. \cite{paper_22} showed that iOS apps perform significantly worse in some security categories when compared to Android apps. All this goes to say that another way our work can be expanded upon is to develop a sister project to ours, which is dedicated to developing iOS MASTG reference applications. If the goal to create a set of MASTG reference apps for improving its educational value is to be further pursued, this would be a natural next step.
